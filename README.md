## Principal work · PRM Studio & `prm` CLI

I am the **principal contributor** of the product: architecture, backend, CMS, and the command-line tool. PRM Studio is a micro-PaaS in the QANTK ecosystem — **The Edge Prompt Delivery Network & Vault**.

Traditional software bakes prompt text into the repo. Every wording change means compile, test, and redeploy. I built PRM to split that concern:

1. Teams keep prompts in a **vault** (CMS + versions + API keys).
2. Apps consume a single **edge endpoint** (`GET /v1/prompts/:human_id`).
3. Edits go live **without touching application infrastructure**.
4. Developers iterate **local-first** with `prm`, then publish once.

```
  App / agent                 Edge CDN                         Studio
  ──────────                  ────────                         ──────
  GET /v1/prompts/:id  ──►    Cloudflare Worker          CMS (OAuth)
  X-API-Key                   render {{vars}} O(N)       CRUD · teams · usage
  query params                SHA-256 key check          JWT → /v1/cms/*
         ▲                    Supabase (serverless)
         │
  prm serve (localhost)  ·  prm studio push / pull
```

### Developer flow (`prm`)

```bash
prm init
prm prompts create --human-id demo --name "Demo" --template "Hola {{nombre}}"
prm serve                          # http://127.0.0.1:8788

prm auth login
prm studio push
```
